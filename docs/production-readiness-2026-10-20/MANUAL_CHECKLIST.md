# Остались только непроверенные сценарии

Владелец попросил пропустить свой Google-вход; повторное подтверждение не запрашивается. Ниже ожидаемые результаты будущей приёмки, а не выполненные проверки. Desktop/mobile публичные/синтетические сценарии перечислены как выполненные в REPORT и здесь не повторяются.

1. **Новый разрешённый Google TEST account после полной анонимной анкеты на localhost:3330.** Закончить настоящий Google login/Clerk callback в течение TTL30мин. Ожидание: поля не вводятся повторно, stable Clerk ID соответствует одному профилю, draft погашен, все поля/дети в изолированной БД, точная цель `/dashboard/events`, reload не требует снова v2. Старый returnTo не перехватывает цель. Сверить другую разрешённую CRM-сессию и выход/повторный настоящий вход. DATA-01/REDIRECT-01, MC-053/066.
2. **Существующий участник обычной кнопкой входа с прямого события.** Ожидание: проверенный реальный профиль после Google, существующая identity без дубля, прежний event returnTo используется только если не нужна новая анкета. При старой версии — обязательный новый фильтр, после него `/dashboard/events`. MC-017.
3. **Новый Google account через «Я уже регистрировался».** Ожидание: до прохождения v2 нет закрытых event props или регистрации, обязательную форму нельзя обойти URL/refresh/action. MC-054.
4. **Google cancel/back, callback replay и две настоящие test identities.** Ожидание: нет циклов и completion при отказе/ошибке записи, nonce/TTL соблюдаются, повтор callback не создаёт дубль, другой аккаунт не присваивает consumed draft. Реальный Clerk logout→back→другой Google account→reload не показывает предыдущие поля/семью. Проверить desktop/mobile. MC-062/065/066.
5. **Исторические synthetic paid/pending билеты и семья.** Ожидание: прежние owner/дети/snapshots/суммы/история читаемы, разрешённые нефинансовые операции честно отображаются; paid нельзя удалить/переписать в ограниченном режиме. Реальную отмену/оплату не выполнять. MC-052.

Внешнее применение SQL, подтверждение проекта/backup, ротация секретов, provider reconciliation и production smoke перечислены отдельно в RELEASE_PLAN/REPORT. Это условия выпуска, а не дополнительные пункты исходной66-матрицы. Пароли, коды и персональные выгрузки в чат не передаются.
