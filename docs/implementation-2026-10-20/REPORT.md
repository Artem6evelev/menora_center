## Действующая матрица прав

Условия: собственная Clerk-сессия, заполненный профиль с новыми ответами; событие существует, запланировано и запись открыта. Роль администратора сама по себе не даёт право личной записи или работы с собственными детьми.

| Профиль | Просмотр события | Запись себя | Добавление/запись своих детей |
|---|---|---|---|
| Гость / неполная анкета / нет новых ответов | Нет | Нет | Нет |
| Материнская линия, женщина | Да | Да | Да |
| Материнская линия, мужчина | Да | Да | Нет, включая старых детей |
| Гиюр, женщина, объединённый ответ без уточнения | Да | Да | Нет до уточнения |
| Гиюр, женщина, продвинутый этап | Да | Да | Нет, включая старых детей |
| Гиюр, женщина, явно завершён | Да | Да | Да |
| Гиюр, мужчина | Пока нет, согласно общему ответу владельца | Пока нет | Нет |
| Нет галахического еврейства | Ресурсный экран | Нет | Нет |
| Admin / superadmin | Да для управления | По личному профилю | Самостоятельно по личному профилю; ручное исключение отдельно |

Основание: [решения владельца OD-01–OD-06](../audit-2026-10-20/SPEC_DECISIONS.md). Завершённость гиюра не выводится из старого текста или объединённого ответа. `giyurStage` можно уточнить одной отдельной формой в профиле/детском кабинете без повторного заполнения полной анкеты.

## Что изменено

- Для гостя navbar без меню; главная не загружает/не сериализует события и не показывает блок ближайших событий. На прямой ссылке — точные заголовок, текст и две ветки из ТЗ; обычные header-кнопки скрыты.
- `/register`: полное приветствие, ровно три основных ответа, отдельный пол, полная существующая анкета раскрывается только для первых двух ответов. Повторный «Статус» удалён. Третья ветка содержит полную благодарность и ссылки, не отправляет скрытую полную анкету.
- Google redirect/callback сохранён на поддерживаемом установленным Clerk API. `/auth/complete` проверяет профиль после входа; новый аккаунт через «я уже регистрировался» возвращается к анкете. Контекст события ограничен allowlist безопасных внутренних URL. Для незавершённой регистрации используется черновик в sessionStorage с TTL 30 минут; существующий завершённый профиль не перезаписывается молча. Сохранён контекст и для Clerk continuation/missing-requirements.
- Единая policy используется UI и сервером. Права берутся из свежей БД; обновление анкеты защищено revision от старого запроса. Все event loaders, собственная регистрация, legacy delegate и все найденные child/profile handlers проверяют доступ и принадлежность.
- Дети остаются в существующем JSON профиля; сервер присваивает стабильные ID/parentId. Клиентский parentId не принимается, чужой/дублированный ID отклоняется. Legacy `child_N` разрешается только в собственном массиве; прежние регистрации получают snapshot детей перед изменением семейных данных. Старые дети отца сохранены и видны без self-service.
- `/dashboard/kids/manual`: staff-only ручная запись ребёнка на событие либо программу, причина, actor, parent/child/target/time в `community_audit`. Статус и собственные права отца не меняются, отсутствующий статус остаётся отсутствующим. Повтор requestId возвращает прежнюю запись и ту же ссылку оплаты; существующая регистрация не перезаписывается автоматически.
- Shutafim открывается прежним iframe. Состав семьи и сумма проверяются сервером **до** формирования URL; произвольный clientAmount и анонимный extraKids не дают обхода. Query-параметры действующей ссылки сохранены. Настройка webhook не изменялась.
- Новый профиль/семья/регистрация сохраняются транзакционно; откат при ошибке БД проверен. Наружу возвращаются только намеренно публичные ошибки, без SQL/внутренних данных. Welcome email сохранён как best-effort после успешного сохранения; в тестах внешняя доставка отключена.

Основные файлы: `lib/community/*`, `actions/community*.ts`, `actions/event.ts`, `actions/event-registration.ts`, `actions/user.ts`, обе старые child actions, `components/community/*`, `components/dashboard/main/onboarding-form.tsx`, profile/kids/event components, marketing/auth/dashboard routes, navbar и sitemap. Полный список — [changed-files.txt](evidence/changed-files.txt).

## Ошибки текущей среды и БД

`videos_author` — не отдельная таблица, а псевдоним `public.users` в relation `videos.author_id → users.id`. `with: { author: ... }` без `columns` выбирал все поля users, в том числе добавленный в ORM `gender`. Read-only проверка фактической БД обнаружила отсутствие всех новых filter-полей. В `actions/video.ts` автор теперь проецируется только в `firstName`, `lastName`, `authorProfile.slug`. Этот запрос проверен **до** миграции и в регрессионном тесте на старой схеме: оба успешны.

По отдельному поручению владельца исправить текущую среду применены только совместимые [0004](../../drizzle/0004_community_filtering.sql) и [0005](../../drizzle/0005_giyur_stage.sql) в одной транзакции. Добавлены nullable `gender`, `affiliation`, `filter_version`, `giyur_stage`; `filter_revision` NOT NULL DEFAULT 0; CHECK-ограничения; отдельный audit с RLS и без публичных policies. Никаких inferred/backfill статусов. Полные JSON-отпечатки бизнес-строк users/events/event_participants/kids_applications/service_participants до и после совпали. Реальные профили, дети, записи и оплаты не редактировались.

Доказательство: [environment-schema-repair.json](evidence/environment-schema-repair.json), исходные metadata — [db-columns-before.json](evidence/db-columns-before.json). Новый запрос видео успешно вернул 8 записей до/после; содержимое записей/контакты в отчёт не выводились. Это БД из локальных env; её соответствие production deployment не установлено. На production приложение не выпускалось.

Существующие истории Drizzle и Supabase расходятся; исторические цепочки не запускались и не переписывались. Применены конкретные два SQL-файла, SHA256 сохранены в evidence; старый mixed migration ledger не объявлен согласованным. Перед следующим выпуском сопоставить baseline и журнал, не запускать обе старые цепочки автоматически.

Для `/logos/menora-logo-dark.svg` добавлена самодостаточная SVG-версия существующего фирменного знака со светлой заливкой, без изменения встроенного исходного изображения. GET этого пути теперь HTTP 200 в текущем dev и изолированном стенде.
