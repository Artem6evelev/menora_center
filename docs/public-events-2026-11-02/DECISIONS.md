# Решения владельца, 02.11.2026

Основание — новое ТЗ «Единый публичный доступ и мягкая фильтрация для Web + Telegram Mini App» и прямое уточнение телефона связи. Эти решения заменяют противоречащие им прежние ограничения просмотра, Russian-only для нового flow и автоматическую подписку при первом /start/bootstrap. Исторические отчёты остаются историческими доказательствами.

1. Просмотр опубликованного публичного мероприятия не требует религиозной анкеты. Проверка допуска выполняется после «Хочу прийти» и повторно перед регистрацией/выдачей оплаты.
2. `events.admission_policy` отдельно от существующей демографической аудитории: `restricted` по умолчанию для всех прежних событий; `open` только явным выбором администратора. Черновики, удалённые, invite-only и административно закрытые события не публикуются.
3. Пять входных самоответов относятся к предварительному интересу. Они не меняют `users.affiliation`, версию фильтра или стадию гиюра. Постоянная анкета сохраняет три категории. Неизвестный статус не равен `none`.
4. Для открытого события обязательны подтверждённая identity, обычные сведения, пол, город и согласие с политикой. Религиозная категория не требуется; отдельный обычный профиль не присваивает её автоматически. При последующем ограниченном действии нужен актуальный постоянный фильтр.
5. Материнская линия и объединённый ответ о гиюре сохраняют собственную запись. Мужчины не получают детских прав. Женщина с гиюром неизвестной/продвинутой стадии записывает себя, а права на детей требует уточнить только при детском действии. Детские права не расширяются открытым мероприятием. Административное исключение сохраняет статус отца.
6. Контакт сохраняется только явной отправкой. Согласие ответить на конкретное обращение обязательно; будущие приглашения — отдельный необязательный выключенный флажок. Просмотр, /start и Mini App bootstrap не подписывают автоматически. Старые согласия/отписки/блокировки не меняются массово. `/subscribe` остаётся явным действием.
7. CRM interest — не билет, не регистрация и не платёж. Гостю не нужен Google-вход. Гостевой контакт не создаёт пользователя Clerk. Связывание допускается только после подтверждённой identity с браузерной capability, без сопоставления по имени/телефону/email.
8. Новые объяснения, короткий вопрос, контакт и отказ от приглашений доступны RU/HE/EN; для HE — RTL. Выбор явный, по умолчанию RU, без определения по Telegram/device metadata. Глобальная локализация website и прежних Kids/payment экранов не переписывается.

10. Только локальный коммит. Публикация, production SQL и изменения внешних сервисов выполняются владельцем отдельно. Существующая оплата Shutafim, схема identity и защита конкурентного сохранения сохраняются.
