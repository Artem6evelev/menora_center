Возвращающийся участник сразу открывает полную страницу события. Старому участнику с заполненным профилем нужен только новый фильтр. После завершения появляется «Анкета готова ✓…»; изменение ответов и возврат внутри onboarding сохраняют событие. Reload также сохраняет назначение. Зарегистрированному участнику показываются статус и «Моя запись». Третья категория остаётся на ресурсах.

7. **Welcome и атрибуция.** `/start` отправляет PNG + HTML caption + inline keyboard на RU/HE/EN. Рекламный вариант использует доступную HTTPS-картинку события, CTA «Открыть мероприятие» и вторичный переход в Menorah Center; обычный — брендовый баннер, вход в Mini App и события. Есть контакт. Название/имя экранируются. Брендовый PNG 1600×900 собран из действующего логотипа: `node scripts/build-telegram-welcome.cjs`; он публикуется вместе с кодом по `/telegram/welcome.png`. Исходный шаблон — в скрипте, отдельный тяжёлый SVG не нужен. При однозначном отклонении фото используется брендовый PNG/текст; при неизвестном результате доставки повторов нет. Сохраняется дедупликация update ID. Контракт сверялся с [официальным Bot API](https://core.telegram.org/bots/api#sendphoto).

   Существующие активные `telegram_campaigns` имеют приоритет над fallback `event_<eventId>`; выключенная запись не оживает через такой fallback. Start-параметр ограничен существующим форматом, остаётся подсказкой навигации. Используются существующие `first_start_param` / `last_start_param`, без второй модели атрибуции. Контекст события закрепляется в URL Mini App. Новый session-protected GET `/api/telegram/miniapp/launch` выдаёт только ограниченное превью planned-события: название, медиа, дата/место, цена, короткий lead. Он не выдаёт полное описание, детей, платежи или чужие записи. Полная страница и checkout независимо сохраняют прежние серверные guards. Для третьей категории превью не выдаётся. Start-параметр никогда не предоставляет доступ к регистрации.

8. **Анонсы — решение владельца от 22.10.2026.** Новое правило заменяет прежний opt-in UI в этой реализации. Настоящий `/start` или успешный проверенный Telegram bootstrap переводит только `unknown` без блокировки в `subscribed`, записывая `marketing_opt_in_at`. Новый контакт создаётся подписанным в этих двух случаях. Остальные сообщения боту не подписывают legacy unknown. Нет массового обновления legacy-контактов. Отписка и блокировка сохраняются при входах; blocked-контакт не получает welcome. `/unsubscribe` отключает анонсы. Явная проверенная `/subscribe` восстанавливает подписку и при необходимости снимает прежний delivery block; автоматические входы блокировку не снимают. Существующие явные subscribe/unsubscribe callbacks/API остаются совместимыми. Поля анкеты и согласие с политикой не менялись.

   На home только вторичный статус без opt-in CTA, toggle и consent card. Welcome прозрачно поясняет анонсы и `/unsubscribe`; отписанному сообщает об отключении. Аудитория очереди по-прежнему требует одновременно `subscribed`, `blocked_at IS NULL`, доступный `telegram_chat_id`, неотключённый аккаунт; состояние перепроверяется перед отправкой. Mini App не выдумывает chat ID из Telegram user ID и не обходит отсутствие разрешённого канала доставки.
