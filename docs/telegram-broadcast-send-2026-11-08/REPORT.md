# Отправка всей Telegram-рассылки одной кнопкой — 08.11.2026

База `main`: `5b9840cc2a6a759915d603955b789ffe1cff7d4e`. Проверена текущая рабочая копия этого релиза. Схема БД, production env, webhook/menu/commands не меняются. Реальная рассылка владельца не запускалась.

## Поведение

- Под живым предпросмотром постоянно видна жёлтая кнопка «Отправить всем выбранным — N получателей». Ручной предварительный «Предпросмотр» необязателен: отправка сначала загружает картинку и проверяет сообщение, событие и получателей сервером, затем запрашивает подтверждение реальной рассылки.
- Один запуск создаёт immutable campaign с прежним request-key и автоматически продолжает только эту рассылку ограниченными серверными запросами. Каждый запрос заново проверяет права сотрудника. Другие незавершённые рассылки не запускаются.
- Видны прогресс, фактически доставленные сообщения, ошибки, недоступные чаты и неопределённые результаты. Прежние «Очередь / Обработать пачку» заменены историей рассылок. У незавершённой рассылки есть «Продолжить отправку» с подтверждением.
- Страницу нужно держать открытой до завершения. После закрытия или сетевого сбоя продолжение доступно из истории. Автоматическую работу при закрытой странице этот интерфейс не обещает. Доставленные и неопределённые сообщения повторно автоматически не отправляются.
- Сохранены global mutex, rate limit/backoff, проверка доступности чата и публичности события перед отправкой, защита от двойного клика и повторного enqueue. Старые статусы подписки не ограничивают доступную аудиторию согласно утверждённому предыдущему решению.
- Исправлен существующий счётчик истории: Drizzle удалял квалификатор Column в single-table projection, из-за чего correlated subquery сравнивал `broadcast_id` с внутренним `id`. Теперь ссылка на внешний `telegram_broadcasts.id` явно квалифицирована; фактические delivered/queued/failed/unknown/skipped считаются отдельно.
- Исправлено немедленное удаление картинки из предпросмотра: устаревший blob URL больше не показывается после смены выбранного файла.
